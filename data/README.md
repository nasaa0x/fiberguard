# Dataset provenance

The default `network.roads.json` snapshot contains all **45 successfully retrieved OSRM / OSM car routes**, including full-provider road distance, a 20 m tolerance simplified road polyline, request URL, fetch timestamp, provider, and surface / fiber verification flags. Source: https://routing.openstreetmap.de/about.html and https://project-osrm.org/. OSM geometry © OpenStreetMap contributors, made available under ODbL 1.0: https://opendatacommons.org/licenses/odbl/1-0/.

The OSRM route is the fastest driving route according to the provider, not a certificate of asphalt-only roads or existing fiber infrastructure. Cost uses road kilometers × the modeled terrain rate, without the coordinate detour factor. Some logical city links share the same roads or pass through other cities; logical edge-disjointness does not prove physical cable diversity.

Refresh using `.venv/bin/python -m scripts.fetch_roads`, which respects a 1.1-second minimum interval and persistent coordinate/profile-specific cache. There is no straight-line fallback for routing failures. The snapshot works offline; refreshing needs an internet connection. Individual updates are available via the API / edge-table road icon. Normal CRUD cannot silently edit externally sourced length or geometry; refresh them together instead.

The original `network.json` coordinate-estimate dataset remains separately generated by `python3 data/generate.py`. Its methodology below applies to that original fallback only.

The 22 cities represent Ulaanbaatar and the 21 aimag capitals. The city coordinates are manually authored approximate reference coordinates, not cadastral / surveyed positions. City names are provided in Mongolian and English transliteration (transliterations can vary).

All 45 candidate adjacencies are explicitly listed **academic planning hypotheses**, chosen between geographically plausible neighbors. They are not a verified national fiber inventory and do not certify rights-of-way or road / railway alignments. Only the road snapshot uses OSRM-returned lengths; coordinate estimates never receive that source label.

- Length: haversine × declared terrain detour.
- CAPEX: length × declared USD/km rate.
- Geometry: deterministic synthetic bent polyline, independent from the scalar detour estimate.
- Terrain, risk, demand, disaster exposure, corridor IDs, and SRLG membership: authored model assumptions.
- `planned` status means eligible in the planning graph, not physically deployed.
- Seed 42 fixes scenario pair sampling. The geographic dataset generator itself does not use randomness.

Every edge records distance and geometry provenance. Validated lengths can replace estimates using the UI or API with an explicit `validation_reference`; surveyed route geometry remains a separate provenance field. See `docs/API.md`.

The authoritative seeded file is never modified by simulation or CRUD. CRUD writes ignored `network.local.json`; stop the server and remove that override to return to the bundled road snapshot. Full mesh connections are created only inside the graph engine in a separate theoretical namespace and never persisted as feasible candidates.

The frontend bundles a coarse Mongolia display boundary from https://github.com/johan/world.geo.json/blob/master/countries/MNG.geo.json. It is for geographic orientation, not a legal / engineering boundary. No external tile imagery is bundled or prefetched.
